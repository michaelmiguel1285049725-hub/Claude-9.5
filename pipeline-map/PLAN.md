# 方案 1：思考流水线地图（Pipeline Map）

配套数据：`bias_map_data.json`（101 个节点、35 条边；字段说明见文件内 `meta`）。

## 0. 一句话定位

把"一个人处理一件事"的过程画成一条从左到右的流水线，每个认知偏差按**它在哪一步把你带偏**放到对应的位置上。主轴回答的问题是：**"我此刻在哪一步出错？"**

## 1. 主轴与三个叠加维度

| 维度 | 编码方式 | 数据字段 |
|---|---|---|
| 错在哪一步（**主轴，决定位置**） | 横向位置 | `stage` / `zone` |
| 学派来源 | 节点颜色（5 色） | `school` |
| 证据可靠性 | 节点样式（实心 / 虚线边框 / 灰色半透明） | `evidence` |

三个维度叠在一张图上，但**只有主轴决定位置**。

## 2. 画布布局

画布横向，建议 16:9 或更宽。自上而下分五层：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 上层：输入污染源                                                        │
│   [D 区 · 看自己]                        [E 区 · 看他人与群体]            │
│        ↓ 箭头指向"估计"和"选择"两站            ↓                          │
├──────────────────────────────────────────────────────────────────────┤
│ 背景层：G 区 · 环境效度                                                 │
│   左端浅色 = 友善环境 ……………… 右端深色 = 恶劣环境                        │
│                                                                      │
│ 主轴：  ① 看到世界 ──▶ ② 估计概率 ──▶ ③ 做选择 ──▶ ④ 行动 ──▶ ⑤ 事后记忆 │
│                        [B 区节点]      [C 区节点]              [F 区节点] │
│                        ((噪声晕))      ((噪声晕))               ((噪声晕)) │
│                                                                      │
│        ◀────────────── 反馈回路（虚线，在恶劣环境段断开）──────────────┘  │
├──────────────────────────────────────────────────────────────────────┤
│ 下层：J 区 · 去偏方法（方块），每个用虚线连到它作用的那一站                  │
│   事前验尸→②   考虑相反面→②   决策清单→②③   默认选项→③   决策日记→⑤        │
├──────────────────────────────────────────────────────────────────────┤
│ 地基：A 区 · 总框架（系统1/2、属性替换、有限理性、生态理性……）横贯全图      │
└──────────────────────────────────────────────────────────────────────┘
      侧栏 / 图例角落：I 区 · 证据可靠性（不占位置，只体现为样式）
```

各区落位规则：

- **B 区**放在②站，**C 区**放在③站，**F 区**放在⑤站。①和④两站没有节点，只是流程标记，保留它们是为了让流水线完整。
- **D、E 区**放在轴上方，各自成一个簇，用箭头指向②和③。它们不是流水线上的一步，是流进流水线的"脏水"。
- **G 区**不画成节点簇，画成整条轴的背景渐变色带；G 区的 8 个概念作为背景色带的标注放在色带两端和中间。
- **H 区**不画成独立节点，每个站点周围画一圈"散布晕"表示噪声；H 区的 4 个概念放在图例里解释这个晕是什么。
- **反馈回路**：从⑤站画一条虚线回到②站，在背景色带的"恶劣环境"段用断口表示回路断裂。这条线表达的是"人为制造反馈"那个杠杆。
- **J 区**放在轴下方，用**方块**（区别于偏差用圆），虚线连到作用站。`edges` 里 `type: targets / uses` 的边就是这些连线。
- **A 区**横贯底部，作为地基条。
- **I 区**只体现在图例：三种节点样式各举一例。

## 3. 视觉编码细则

**颜色（`school`）**，5 种，建议低饱和度：
- `kahneman` 一种主色（这是"可单独抽出"的层，颜色要最醒目）
- `thaler` 、`social` 、`critique` 、`expertise` 各一种
- `debias` 与 `meta` 用中性灰，因为它们不是偏差本身

**样式（`evidence`）**：
- `solid` → 实心填充
- `contested` → 虚线边框、填充淡化
- `refuted` → 灰色、半透明、可加删除线；**必须留在图上**，它们的作用是"这块砖别用"

**形状**：偏差用圆或圆角矩形，去偏方法用方块，总框架用长条。

**节点面上只放**：中文名 + 英文名 + 年份。`one_liner` 和 `source` 放进点击后的卡片，不放在图面上。

**节点大小全部相等**。不要用大小表达"重要性"。

**连线**只画 `edges` 里的 35 条，不要自行补充"看起来相关"的连线。`explains / derives / component` 用实线，`targets / uses / reduces / limits` 用虚线，箭头方向按 `from → to`。

## 4. 交互

三级缩放（渐进披露）：
1. **最远**：只显示 5 个站名 + 10 个区的名字 + 图例，不显示任何节点
2. **中间**：显示节点名（中英文 + 年份）
3. **最近**：节点周围显示 `one_liner`

图层开关（三个）：
- **只看卡尼曼**：`school == kahneman` 以外的节点变半透明
- **只看某学派**：按 `school` 筛选
- **只看硬证据**：隐藏 `contested` 和 `refuted`

点击节点 → 侧边卡片：中英文名、`one_liner`、`source`、证据状态、以及它在 `edges` 里连到的节点（可点击跳转）。

悬停某站 → 高亮该站的所有节点 + 连到它的去偏方法。

## 5. 构建顺序（重要）

不要一次生成成品。按这个顺序：

1. **只画骨架**：5 个站、10 个区的位置、背景色带、反馈回路、图例。不放任何节点。检查布局对不对。
2. 放入 `school == kahneman` 的节点（约 35 个），检查②③⑤三站的密度是否可读。
3. 放入其余节点。
4. 加连线（35 条）。
5. 加交互。

每一步之间停下来看。

## 6. 不要做的事

- 不要用节点大小表达重要性
- 不要删掉 `refuted` 节点
- 不要自行添加数据文件之外的概念或连线
- 不要把 `one_liner` 铺在图面上（会爆）
- 不要把去偏方法和偏差画成同一种形状
- 不要给节点配插图或图标，信息密度已经够高
