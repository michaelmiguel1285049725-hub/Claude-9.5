01

为什么要做

三个真实痛点

① 评分没有外部锚点

现有 9 维内容评分只有「评分器自己觉得好」一个依据，没有外部锚点。

存在 Goodhart 问题：评分惩罚了引擎可能喜欢的结构，例如「关键要点 / FAQ」这类设计性冗余。

对应 → 第一层 用 第二层 引用数据校准（第 3 节）

② 结论不透明，出过事故

此前分析出现过分母错误导致结论撤回。

根因：全靠 AI 自由发挥、无人把关；结论的来源和硬度不透明。

对应 → 结论标签 + 判灯规则 + 沉淀手册（第 7 节）

③ 引擎侧数据噪声大

AI 回答本质随机，单次读数没有意义。

工具覆盖有盲区（部分引擎测不到）。

对应 → 第二层 读数规则（第 5 节）+ Semrush 边界（第 6 节）

03

主线：用第二层真实引用数据校准第一层评分

「校准」= 两张表按 URL 合并，分组比均值

结论只到这三种

有效该维度两组有差异
无效该维度两组没差异
有害方向反了：被引的反而得分低 → 最可能就是 Goodhart 矛盾的证据

不做的事

  • 不解释单篇为什么被引
  • 不追溯生成过程
  • 不谈因果

两个版本

校准 v0（本期）：用已有的被引 URL 清单做；未引组必须从同一批次（8 月后）、同意图随机抽样，否则比出来的是生产方式差异。

校准 v1（后续）：等试卷 v1.0 跑满 3–4 周后重做。

04

试卷（黄金评测集）设计

第二层 的仪器

意图 × 问题家族 × 措辞变体 × 语言（中 / 英 / 粤） × 引擎

按「意图」不按「措辞」

同一意图的十种问法是十次采样，不是十个覆盖点。

问题家族

是什么怎么选（比较）怎么做哪里买值不值有什么风险
引擎对不同家族处理方式不同；比较类影响力最高。

分两份

优化集：用来校准和看效果。

保留集：大家知道存在，单独 campaign；规则是「不用它做任何调整决策」，最终汇报用它。

版本规则

  • 冻结、编版本号、只加不删
  • 加题不影响旧题的时间序列；改措辞和删题才会

来源

以港新用户原话为主：客服高频问题、站内搜索词、论坛 / 小红书原话。

待定 Semrush 缺口 prompt 是否可入试卷：8 月起内容生产已用它做种子，若试卷同源则是「照着答案出题」，需团队讨论。

第二个下游：存量打标

同一张「意图 × 家族」分类表还用来给存量文章打标，这是主线合并的前提。本期只打 8 月以来批次 + 被引页面所在批次，不打全量。

05

噪声与样本量

读数规则 · 第二层

AI 回答是随机的

同一 prompt 重跑，被引域名重复率很低。单次读数没有意义。

误差 ≈ ±2 × √( p(1−p) / n ) n = 30 → 约 ±17 个百分点 · n = 300 → 约 ±5 个百分点 · 误差减半，数据需翻四倍
样本量 n误差（约）含义
30±17 个百分点只能看到很大的变化
300±5 个百分点能分辨中等变化
×4误差减半靠时间和 prompt 数量积累

因此的读数规则

  • 按周读不按天读
  • 优化前后对比，至少各积累 3–4 周
  • 多 prompt 优先于多次数

跨引擎的数字永远不比

各引擎基础率不同（如每个回答引用的来源数量不同）。只在同引擎内比时间、比竞品。

周报模板

把基础率印在数字旁边；每个数字带样本数和误差范围（横向规则 2）。

Semrush 定位

能做 / 做不到 · 第二层 记分员

Prompt Tracking = 跑我们试卷的记分员

真实运行，可信度最高。

大盘 / Prompt Research = 出题参考书

只看格局，绝不当 KPI。
能做
  • ChatGPT / Google AI Mode / Gemini 上的提及率、引用、平均位置
  • 可选香港地区
  • 每天跑一次
做不到
  • Perplexity、Claude、国内 AI 引擎（未覆盖）
  • 「吸收度」（页面对答案的贡献深度，需原始回答全文自算）
  • 一天多次采样
  • 待核实 prompt 上限、原始回答能否导出、品牌别名配置、历史保留、API
报告规则：永远按引擎分开；底部固定一行「本报告未覆盖引擎」。
缺口：由自建采集脚本补（独立排期，见第 10 节）。

主要风险与边界

A样本稀疏

被引页面是稀疏事件，校准 v0 只能证伪有害维度，不能重新标定 9 个权重。

B候选池

页面要先进入引擎候选池（可抓取、已索引）才谈内容质量；专门域名 [N] 篇文章的索引率是最大杠杆之一，本期必查。

C顺序

先跑基线再改评分；用引用数据校准评分本身会制造下一轮 Goodhart，解法是优化集 / 保留集分离。

D时间

校准 v1 在 10.16 前不会有结果；答辩能展示的是：体系 + 基线读数 + 校准 v0 + 「做不到什么」清单。

E同源

内容生产种子与试卷若同来自 Semrush，测量会自我循环。待团队讨论

§数据边界

  • 敏感数据 = 公司内部数据看板数据（如 DAU、GMV 变化），只在公司环境处理
  • 自产代码 / 数据与 Semrush 数据可在 Claude Code 工作，最终由技术部署到阿里云代码库
  • 密钥不进任何仓库
